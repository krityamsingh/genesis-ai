OWASP TOP 10 SCAN RULES:

1. SQL INJECTION — look for user input directly concatenated into SQL queries
   Bad: f"SELECT * FROM users WHERE name = '{user_input}'"
   Look for: string formatting/concatenation with SQL, no parameterised queries

2. XSS — Cross-Site Scripting — unsanitised input rendered in HTML
   Look for: user input placed into innerHTML, template strings, or response bodies

3. COMMAND INJECTION — user input passed to shell commands
   Look for: subprocess, os.system, exec with user-controlled data

4. PATH TRAVERSAL — user input used in file paths
   Look for: open(), os.path.join() with unsanitised user input containing ../

5. HARDCODED SECRETS — API keys, passwords, tokens in code
   Look for: strings that look like keys (long random strings, JWT tokens, passwords)
   Patterns: API_KEY = "...", password = "...", secret = "...", token = "..."

6. INSECURE DESERIALIZATION
   Look for: pickle.loads(), yaml.load() without Loader=yaml.SafeLoader

7. BROKEN AUTHENTICATION
   Look for: weak password hashing (MD5, SHA1), no rate limiting on login

8. SENSITIVE DATA EXPOSURE
   Look for: logging passwords, credit cards, SSNs, API keys

9. SSRF — Server-Side Request Forgery
   Look for: requests.get(user_input) with no URL validation

10. INSECURE DIRECT OBJECT REFERENCES
    Look for: using user-supplied IDs to access database records without auth check
